What seismic data is, in plain words

A seismic file is a bundle of recordings of the ground shaking, one recording per sensor, all started at the same instant.

You do not need any geophysics to use SeisConv, but you do need four words. They are the only vocabulary Part I assumes, and every one of them is defined here.

Sample, trace, record, header

  • Sample - one number. It is how hard the ground pushed on one sensor at one instant. A sample carries no physical unit of its own: it is whatever number the recorder wrote down. SeisConv therefore always labels the vertical axis "Amplitude (sample value)" and never pretends it is millivolts or anything else.
  • Trace - one sensor's whole recording, which is a long list of samples in time order. If the recorder takes a sample every 2 milliseconds for 2 seconds, that trace is 1000 samples long. The gap between samples is the sample interval (often written dt); 2 ms is a common one.
  • Record (also called a shot record or shot gather) - every trace from one bang. You fire a source - a weight drop, an explosive charge, a vibrator truck - and every geophone on the line records at once. Ninety-six geophones give a record of 96 traces. One file usually holds one record, sometimes many.
  • Header - the label on the tin. Beside the numbers, the file carries fields saying how many traces there are, how long each one is, what the sample interval was, which shot this was, and often where the source and each receiver stood on the ground. When people say "the geometry is wrong", they mean those position fields are wrong.

Why there are half a dozen incompatible formats

The recorder in the field, the QC laptop and the processing house were each built by different companies in different decades, and each wrote the numbers down its own way. The arrangement of samples and headers inside the file is the format. The common ones, all of which SeisConv reads and writes:

  • SEG-D - what many recorders write in the field, straight off the instrument.
  • SEG-Y - the exchange format almost every processing system expects. It comes in revisions 0, 1 and 2, which differ in what the headers are allowed to contain.
  • SEG-2 (files often named .dat) - common on engineering and shallow-seismic instruments.
  • SU - Seismic Unix; a bare stream of traces with no reel header at all.

They hold the same physics. Converting between them is moving the same samples into a different arrangement of bytes, and that is the job the Converter tab does.

And the geometry files

Where each source and receiver actually stood is normally kept in a separate set of files, not in the seismic file. The usual one is an SPS triplet: an S file listing the source points, an R file listing the receiver points, and an X file (the "cross-reference" or relation file) saying which receivers listened to which shot. SeisConv also reads the same information when it arrives as SEG-P1, IOGP P1/11 or P6/11, or as a plain coordinate CSV.

If a sentence later in this manual uses a word that was not defined here, it belongs in the Glossary at the back; check there before assuming it matters.

Installing and starting SeisConv

Download one installer, click through a SmartScreen warning that is expected, and start it - there is no account, no licence key and no internet connection required afterwards.

What you need

Windows 10 or 11, 64-bit. macOS and Linux targets exist in the build configuration but are not built or distributed, so on those platforms you would build from source.

Installing

  1. Download the installer, named SeisConv-Setup-<version>.exe, from the project's releases page.
  2. Run it. It lets you choose the installation directory. By default it installs for you alone and needs no administrator rights; there is an option to elevate and install for all users on the machine.
  3. Windows will warn you, and that is expected. The installer is not code-signed, so SmartScreen shows "Windows protected your PC" with only a Don't run button visible. Click More info, then Run anyway. That warning means the file has no purchased signing certificate attached; it is not a statement that anything is wrong with the download. If your site blocks unsigned installers, that is a decision for your IT department rather than something to work around.

First launch, and the promise the app makes

SeisConv runs entirely on your machine. There is no account to create, no sign-in, no licence server, and your data never leaves the computer. The one exception is deliberate and visible: map backgrounds on the SPS and SPS Creation tabs, and the optional basemap layer in the GeoTIFF export, download map tiles from the internet when you switch them on. Everything else works with the network cable out, which is the normal state of a field laptop.

Checking that the version matches this manual

This manual's cover names the exact version it describes, and its reference chapters were generated from that version's own source. The same text, from the same source, is in the app: press ? on any tab to open it, as in .

If the version on the cover and the version you are running differ, trust the app: press ? and read its Help, then get the manual that matches your build.

The window itself

SeisConv draws its own title bar rather than using Windows'. The three buttons at the top right are therefore app buttons: Minimize, Maximize / Restore and Close. Beside them sit Dark and Light (the theme), Audit log and signature and Send feedback. At the bottom right of the status bar are three zoom controls - Zoom out, the percentage (click it to reset to 100%) and Zoom in - which scale the whole interface, and match Ctrl with -, 0 and =.

Sign your work once

Open Audit log and signature in the header, put your name in the Signature box and click Save. Every change you make afterwards is recorded against that name, which is what makes an exported log or a rewritten geometry file defensible weeks later. Do it now, before you touch data: otherwise the app asks for it the first time you do something it audits, and it asks in the middle of whatever you were doing.

The twelve tabs, one sentence each

The icon rail down the left side switches between twelve tabs; here is what each is for, in rail order.

  1. Converter - convert one file, or a whole folder at once, into another format.
  2. Trace Inspector - look at one trace at a time as a waveform or a spectrum, with that trace's header fields beside it.
  3. File Viewer - see the whole record at once as a section image, and run the trace health scan and first-break picking over it.
  4. SPS - load, plot, QC, reproject and re-export survey geometry, on a plain grid or over a real map.
  5. SPS Creation - draw acquisition lines on a map, or import a pre-plot, and generate a fresh SPS survey from them.
  6. Geometry QC - cross-check the open seismic file's header geometry against the loaded survey, diff as-laid against pre-plot, and stamp survey coordinates into a SEG-Y.
  7. Velocity - compute an NMO semblance panel and pick a stacking-velocity function on it.
  8. Spectrum - the record's frequency content, as an average amplitude spectrum, a spectrogram, or an F-K panel.
  9. Trace Workbench - collect traces from one file or several and compare them against each other.
  10. Observer Log - the per-shot field log: build it from a wizard, fill it as you shoot, and export it.
  11. Sweeps - design a vibroseis pilot sweep, inspect it, export it, and QC a recorded sweep against the design.
  12. WiFiSync - keep a folder identical on two machines over WiFi, with no router, no cloud and no account.

Number keys 1 to 9 jump to the first nine of those, in exactly that order, and O goes to the Observer Log. Sweeps and WiFiSync have no key; click them on the rail. All of these keys are ignored while you are typing in a box, so a note containing a digit or an "o" stays in the field. The full key list is Appendix B, and it is read out of the app's own key handler, so it cannot drift from the app.

One open file, shared by every tab. This is the single most useful thing to understand about the app. When you open a seismic file - from the header, from any tab's Open file… button, or with Ctrl+O - every tab is now working on that same file. Open it once in the Converter and it is already waiting in the Trace Inspector, the File Viewer, the Spectrum tab and Geometry QC. The header centre shows what is loaded: the seismic file, and separately the SPS survey, each showing "-" when nothing is loaded. Clear forgets it again, everywhere.

Opening your first file and looking at it

Open the file, read back what SeisConv says it found, then look at one trace and at the whole record.

Open it

  1. Press 1 for the Converter. It starts in single-file mode - the Convert single file card is selected, as in .
  2. Click Pick a seismic file… and choose your file. You do not have to tell SeisConv what format it is, what revision, how the samples are encoded or which way round the bytes go: it works all of that out by reading the file.

Read back what it found

The panel now describes the file: its format and revision, how many traces it holds, how many samples each trace has, and the sample interval. Read this before anything else. It is the app telling you what it believes it just opened, and it is the cheapest QC you will ever do. Two things it catches immediately:

  • The trace count is not what the crew shot - so the file is truncated, or it is not the record you thought it was.
  • The sample interval is 1 ms when the recorder was set to 2 ms - so the instrument settings and the paperwork disagree.

Look at one trace

Press 2 for the Trace Inspector. The file is already there. You get one trace drawn as a waveform, with its header fields beside it, and a slider plus ‹ Prev / Next › to step through the traces. Hovering the plot reads out time and amplitude at the cursor. Waveform and Spectrum switch between the trace itself and its frequency content; +, − and Fit zoom the time axis; and Box-zoom a region lets you drag a box to open that patch enlarged (Esc leaves that mode).

What you are checking on a first pass: does the trace look like ground motion - quiet, then a sharp arrival, then decaying shaking - or does it look like a flat line (a dead channel), or like fuzz with no arrival at all (a noisy one)?

Look at the whole record

Press 3 for the File Viewer. Now every trace is drawn side by side, time running down, so the record reads as a picture. Gain brightens it, the display Mode chooses how each trace is drawn (Variable Density, Wiggle, Variable Area, or VD + Wiggle), and the colour picker offers Seismic, Gray, Amber and Viridis.

The one control worth understanding on day one is AGC. Seismic energy gets weaker with time, so the top of a record is loud and the bottom is faint: the deep reflections are there, but too small to see beside the shallow ones. AGC (automatic gain control) rescales each part of each trace against its own neighbourhood, so late, weak events become visible. Compare with : the same file, the same data, AGC off and on.

AGC is a display setting. It changes how the picture looks, never the samples in the file, and nothing you export is affected by it.

If the file sits in a folder of similar files, [ and ] step to the previous and next file in that folder without going back to a dialog - which is how you flick through a morning's shots.

Converting a file and saving the result

Pick the output format, decide what the file will be called, click Convert & Save, then re-open the result and check it.

The shortest honest path

  1. Open the file, as in the previous chapter. Do not skip reading back what SeisConv says it found.
  2. On the Converter, in the Output format row, click the chip you need. There is one chip per format the app can write as a single file. If you do not know which, the answer is almost always SEG-Y Rev 1: it is what processing systems expect. The exact list, and which formats are offered in single-file versus folder mode, is in About this release at the front of this manual, where it is read out of the app's own writer registry.
  3. Scroll down to the output-name builder and decide what the file will be called (below).
  4. Click Convert & Save…, choose where the file goes in the save dialog that opens, and confirm. When it has finished, an Open folder button appears that takes you straight to the saved file.

Naming the output

Rather than typing a name, you switch on the pieces you want and the app assembles them. The toggles are Original name, Format, Date YYYYMMDD, Time HHMM, Sequence # (batch mode) and Custom text, and the Separator control joins them with an underscore, a hyphen or nothing. The preview updates as you click, so you see the filename you are about to create before you create it. Original name plus Format is a sensible default: it keeps the shot identifiable and records what you turned it into.

Converting a whole folder

Switch the mode card to Convert a folder (batch) - or press Ctrl+B from anywhere. Point Pick folder… at the folder of inputs, choose the format, choose a destination with Pick destination…, then click the run button, which names the count it is about to do ("Convert 3 files"). It stays disabled until it has everything it needs: a folder with seismic files in it, a format and a destination. Clear empties the list, and Cancel appears while a run is in progress and stops it.

Check the result, every time

A conversion you have not checked is a conversion you are guessing about. It takes twenty seconds:

  1. Open the file you just wrote, the same way you opened the input.
  2. Compare what SeisConv reports about it against the input: trace count, sample count and sample interval must all match, and the format and revision should be the one you asked for.
  3. Press 3 and look at the section. It should look like the same record you started with.

If the trace count dropped, something in the input was rejected rather than silently copied - which is deliberate: SeisConv collects malformed records as errors instead of writing out a plausible-looking lie. Recipe 10 in Part II works through what to do next.

Two honest limits worth knowing before you rely on an output. CSV is an export only: it writes the samples as plain numbers, and SeisConv cannot read it back as seismic data. And SeisConv-written SEG-D round-trips correctly through SeisConv's own reader, but interchange with acquisition-vendor software has not been independently verified - check it in the receiving system before you depend on it.

That is Part I. You can now open an unknown file, say what it is, look at it as a trace and as a record, convert it to what processing asked for, and check that what you wrote is what you meant. That is a useful person on a crew.
